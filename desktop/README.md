# Accnotify 电脑端

基于 Tauri 2，支持 Windows 和 macOS，使用系统 WebView，不再附带 Chromium 和 Node.js。关闭窗口后继续在托盘接收消息，使用托盘菜单“退出”才能完全退出；开机启动需安装打包后的客户端。

1. 在“设置”添加或选择服务器，设置电脑名称，点击“保存”或“连接 / 同步”。初次连接生成独立推送 ID；首次使用官方服务器需确认使用声明。支持编辑、删除和切换服务器，至少保留一个地址。
2. 复制 Push 链接向当前 ID 的全部设备发送消息；“复制本机 Push 链接”只向当前电脑发送。
3. 需要共用 ID 时，在“绑定已有 ID”粘贴同一服务器上的 Push 链接，发送验证码，在被选中的确认设备的历史消息里查看验证码并输入。5 分钟内有效，最多尝试 5 次。
4. 每台设备都有独立的设备标识、RSA 密钥、连接凭据和本地历史。“同 ID 的设备”中可复制某台设备的专属推送链接或移除设备。手机、电脑均可独立使用或加入已有 ID。
5. “解除绑定”会生成新的独立 ID，保留本地历史；其他设备继续使用原共用 ID。绑定前的独立推送链接失效，已有历史不合并。

推送默认发给同 ID 的全部设备。加 `"target":"pc"` 只发全部电脑，`"target":"mobile"` 只发全部手机；想发给某一台就用它的设备标识。也可以在 Push 或 Webhook 链接后加 `?target=pc`。指定的设备或类型不存在时返回错误。

历史汇总本机各服务器的消息，支持标题、正文和分组搜索、按分组筛选、复制正文、单条删除和清空全部。详情支持 Markdown、JSON 格式化和查看原始内容，网络图片与 Base64 图片可预览、放大、保存。系统支持 Web Share 时可直接分享图片，否则提供保存后分享的操作。图片最大 8 MB，支持 PNG、JPEG、GIF 和 WebP。服务器发来相同 `id` 会更新原消息，带 `delete` 会删除；各服务器的身份与消息修订仍独立保存。

系统通知可点击打开消息，有链接的消息提供“打开链接”按钮；解密失败会显示系统提醒。当前 Tauri 通知插件不支持桌面通知图片附件或 Android 式分组汇总，因此图片与分组在客户端历史中查看。macOS 和 Windows 上，消息更新、删除或本地清空后，已经显示在系统通知中心的提醒可能仍保留，需要手动清除。Windows 通知进入通知中心后，点击回调可能不可用；客户端历史仍正常更新。

手机端和电脑端的提醒高级设置默认折叠。提醒设置支持工作日、指定星期和时段、每日静默、节假日和自定义日期。它只控制系统通知，消息始终保存到历史；跨午夜时段按开始日期归属，开始结束相同表示全天。静默结束后不补弹旧消息。提醒按本机时区判断。

节假日仅在设置中点击“获取本年度节假日”时请求 `https://timor.tech/api/holiday/year/年份`，数据保存在本地，不会自动获取、更新或重试。再次获取已保存的年度会确认；失败保留旧数据。未获取年度数据时，工作日按周一至周五判断。也可导入本地 JSON：

```json
{"year":2026,"holidays":["2026-01-01"],"workdays":[]}
```

以上为格式示例，并非完整年度日历。`holidays` 是放假日期，`workdays` 是调休上班日期；自定义日期覆盖日历判定。

“通用信息设置”可查看、复制、编辑公用密钥和生成新的公用 ID。当前服务器可以分别选择复用公用 ID、公用密钥；公用值仅供本机不同服务器复用，不会自动同步到其他设备。修改公用密钥后，复用它的服务器随之更新；修改公用 ID 不会自动替换已保存的服务器 ID，需要对目标服务器重新应用。退出密钥复用时保留当前有效密钥，独立密钥可以另行保存或清除，也可查看、复制已保存的当前服务器密钥。可重新生成独立 ID。切换 ID 会保留本地历史；已有设备绑定或待处理绑定时，需先解除或完成绑定。

设置支持白、蓝、绿、红、粉、黑主题色和亮色、暗色、跟随系统模式，默认白色主题。“设备操作”中可仅重置 RSA、重置 ID 和 RSA 或注销设备，只影响当前服务器的本机。重置候选密钥先加密落盘，服务端确认后切换；网络失败时重试同一种操作。本地历史保留。

“关于”显示当前版本和系统，提供项目主页、发布页面、使用教程、测试消息、隐私说明和手动检查更新。检查使用 GitHub Releases，只匹配当前系统和架构的正式电脑端安装包，不会把 Android 发布当作电脑端更新。发现新版后可打开发布页面自行下载，不会自动下载或安装。

发送端加密密钥需要在每台设备分别配置，绑定不会自动同步密钥。电脑端的 RSA 私钥、设备凭据和发送端密钥使用系统密钥存储加密保存；历史消息只保存在本机。离线补发期限仍为 5 分钟，各端分别确认收件。

## 开发与打包

需要 Node.js、Rust 1.90 或更新的稳定版，以及目标系统的开发工具（macOS 使用 Xcode Command Line Tools；Windows 使用 Visual Studio C++ Build Tools 和 WebView2）。依赖需要在允许联网的环境安装，或事先准备离线依赖。依赖齐备后，可执行以下命令。

```bash
npm install
npm start
npm run check
npm run package:mac
npm run package:win
```

macOS 默认使用本地 ad-hoc 签名的非公证 APP 和 DMG，Windows 生成 NSIS 安装包。建议分别在目标系统打包验证。构建产物位于 `desktop/src-tauri/target/release/bundle/`，不提交依赖或打包产物。

版本唯一来源为根目录 `VERSION`。上述 npm 命令会先同步桌面版本；直接调用 Cargo 前，在项目根目录运行 `node scripts/sync-version.mjs`。不要独立修改 package.json、Cargo.toml 或 Tauri 配置中的版本。GitHub 版本标签发布和 PR 的 `build-test` 试构建流程见[项目说明](../README.md#客户端版本与自动打包)。CI 指定目标架构时，产物位于 `target/<目标架构>/release/bundle/`。

项目尚未上线，客户端按全新安装设计，不提供旧版本数据兼容或迁移。首次连接生成独立推送 ID，之后在本机正常保存身份、设置和历史。

当前桌面数据使用应用数据目录下的 `client-v1` 子目录，目录编号标识数据结构，不随应用版本递增。开发期间数据结构不兼容时改用新的目录编号，按全新安装初始化；不读取先前测试目录中的配置。

Tauri 桌面版的应用标识为 `cn.trah.accnotify.desktop`，系统通知和密钥存储使用同一标识，与之前测试应用的系统注册分开。macOS 通知使用应用包中的彩色图标，菜单栏使用透明背景的单色图形。安装到“应用程序”后启动，并允许系统通知；不会迁移此前测试应用的数据或通知授权。

身份与密钥通过系统密钥存储中的随机密钥加密保存，网页界面无法读取私钥或连接凭据。网络请求和消息解密在 Rust 后端执行，界面仅能调用明确列出的客户端操作。
